# Этапы реализации

Библиотечное API, движок диалогов и рабочие операции соединены в одном ядре.
Завершённость реализации в таблице не означает завершённую проверку релиза:
текущие изменения проверяются компиляцией и точечными тестами, интеграция
с клиентом ещё требует отдельного прогона.
Маркеров `M<N>_PENDING` у операций больше нет: доступность определяется правами,
конфигурацией и состоянием нужного компонента.

| Этап | Реализовано |
|---|---|
| M1 | SQLite, библиотечное API, RPC, SDK модулей, провайдеры |
| M2 | Вход речи, цикл туров, лента items, доставка, отмена, хуки, компакция, fallback, картинки |
| M3 | Память, заметки, поиск по чатам, локальные эмбеддинги и гигиена контекста |
| M4 | Каталог и видимость инструментов, загрузка резерва, warm-наборы, статистика, крон, сон, GC |
| M5 | Подагенты, файловые операции и shell, план, вопросы, разрешения, вложения |

Поведение подсистем описано в главах [Туры](turns.md), [Инструменты](tools.md)
и [Рабочие операции](work.md). Полный каталог внешних операций —
[Библиотечное API](api.md).

## Границы текущего поведения

- Клиент хранит последний `seq` ленты и после реконнекта заново вызывает
  `turns.attach`. SDK восстанавливает соединение, а восстановлением подписки
  управляет вызывающий код.
- Файловые операции и `shell_exec` используют возможности `eva-hands`;
  интерактивные shell-сессии не входят в текущий набор инструментов.
- `notes.list` отвечает `unavailable`, если `notes.enabled: false`.
- Модули с capability `ask` показывают запросы вопросов и разрешений.
  Без доступного канала подтверждения рабочая операция не получает разрешение.
