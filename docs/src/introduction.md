# Введение

Ева — персональный агент, который работает постоянно: ведёт чаты на разных поверхностях (клиенты хозяина, мессенджеры), помнит между чатами, пользуется инструментами, выполняет задачи по расписанию и по ночам приводит память в порядок. Человек, которому она служит, в документации называется **хозяином**.

**Ядро** (`eva-kernel`) — один процесс поверх одного SQLite-файла, единственный владелец состояния Евы. Всё остальное — **модули**: отдельные процессы, которые говорят с ядром по msgpack-RPC. Сервисы (мосты, MCP) слушают unix-сокет или TCP, и ядро само звонит им по реестру под Noise; клиенты хозяина звонят ядру сами через unix-сокет, WebSocket или WebSocket поверх TLS.

## Что делает ядро, что делают модули

| Ядро | Модули |
|---|---|
| Чаты, папки, поверхности (surface), история | Каналы связи: клиенты хозяина (телефон, терминал, десктоп), мосты в мессенджеры. Служебный модуль сам создаёт свою surface, ядро запоминает создателя |
| Личности и их адреса на поверхностях, доверие | Сообщают только «кто говорит и где»; флаги доверия ядро вычисляет само |
| Память, заметки, статистика, расход | Своё состояние хранят в песочнице ядра: `fs`, `sqlite`, `kv` |
| Инференс: встроенные провайдеры за трейтом `Provider` | Удалённый провайдер — только как запасной вход, если конфиг его явно называет |
| Инструменты, крон, сон, сборка мусора (с M4) | Объявляют свои инструменты, хуки и подписки на события |
| Руки (`fs_*`/`shell_*`) через библиотеку [`eva-hands`](https://git.desu.church/eva/hands) (с M5) | Рук не исполняют |

У модуля нет доступа к базе ядра. Любое чтение и запись — операция библиотечного API, и права на неё проверяет само ядро. Подробно — в главе [Безопасность](security.md).

## Состояние

Готов этап **M1**:

- библиотечное API: все операции, кроме диалогового движка (туров), поиска по чатам и каталога инструментов;
- схема SQLite (миграция `0001_init`), раннер миграций, сид встроенных сущностей;
- RPC-сервер модулей (msgpack): дозвон сервисов реестра по uds/tcp под Noise, слушатель клиентов uds/ws/wss с токеном, рассылка событий;
- `eva-sdk` для написания модулей;
- провайдеры: OpenAI-совместимый (OpenRouter по умолчанию, диалект `plain` для vLLM и llama-server) и сценарный `mock`.

Ядро в M1 не ведёт диалог: операции, которые требуют движка туров, отвечают ошибкой `unavailable` с маркером этапа. Полный список — в [Дорожной карте](roadmap.md).
