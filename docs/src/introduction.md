# Введение

Ева — персональный агент, который работает постоянно: ведёт чаты на разных поверхностях (клиенты хозяина, мессенджеры), помнит между чатами, пользуется инструментами, выполняет задачи по расписанию и по ночам приводит память в порядок. Человек, которому она служит, в документации называется **хозяином**.

**Soul** (`eva-soul`) — один процесс поверх одного SQLite-файла, единственный владелец состояния Евы. Всё остальное — **модули**: отдельные процессы, которые говорят с soul по msgpack-RPC. Сервисы (мосты, MCP) слушают unix-сокет или TCP, и soul сам звонит им по реестру под Noise; клиенты хозяина сами звонят в soul через unix-сокет, WebSocket или WebSocket поверх TLS.

## Что делает soul, что делают модули

| Soul | Модули |
|---|---|
| Чаты, папки, поверхности (surface), история | Каналы связи: клиенты хозяина (телефон, терминал, десктоп), мосты в мессенджеры. Служебный модуль сам создаёт свою surface, soul запоминает создателя |
| Личности и их адреса на поверхностях, доверие | Сообщают только «кто говорит и где»; флаги доверия soul вычисляет сам |
| Память, заметки, статистика, расход | Своё состояние хранят в песочнице soul: `fs`, `sqlite`, `kv` |
| Инференс: встроенные провайдеры за трейтом `Provider` | Удалённый провайдер — только как запасной вход, если конфиг его явно называет |
| Инструменты, крон, сон, сборка мусора | Объявляют свои инструменты, хуки и подписки на события |
| Руки (`fs_*`/`shell_exec`) через библиотеку [`eva-hands`](https://github.com/eva-rs/hands) | Рук не исполняют |

У модуля нет доступа к базе soul. Любое чтение и запись — операция библиотечного API, и права на неё проверяет сам soul. Подробно — в главе [Безопасность](security.md).

## Состояние

Реализованы основные подсистемы M1–M5:

- диалоговый движок, лента тура с восстановлением после обрыва, отмена, компакция, повторы и запасные модели;
- память, заметки, поиск по чатам, каталог и загрузка инструментов, крон, сон и сборка мусора;
- файловые операции, shell, вложения, подагенты, план и вопросы с разрешениями;
- схема SQLite (миграция `0001_init`), раннер миграций, сид встроенных сущностей;
- RPC-сервер модулей (msgpack): дозвон сервисов реестра по uds/tcp под Noise, слушатель клиентов uds/ws/wss с токеном и HTTP-мост JSON-RPC, рассылка событий;
- `eva-sdk` для написания модулей;
- провайдеры: OpenAI-совместимый (OpenRouter по умолчанию, диалект `plain` для vLLM и llama-server), сценарный `mock` и локальные эмбеддинги `embed_local`.

Устройство диалога описано в главе [Туры](turns.md), рабочие операции — в главе
[Рабочие операции](work.md). Перед первым запуском нужен файл персоны:
по умолчанию `persona.md` внутри `system.state_dir`.
