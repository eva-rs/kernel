# Безопасность

Модель угроз ядра: любой служебный модуль может быть взломан. Мост в мессенджер, получивший чужой код, не должен дотянуться до чатов хозяина, его памяти и личностей и не должен уметь поднять себе доверие. Поэтому права задаются токеном, а проверяет их библиотека ядра, а не транспорт и не модуль.

## Вызывающие и их права

| Caller | Откуда | Права |
|---|---|---|
| `kernel` | Само ядро: инструменты модели, крон, сон, GC, уведомления | Всё, кроме песочницы `fs`/`sqlite`/`kv` и `surfaces.create`; только ему доступен `chats.notify` и поле `issued_by` у `modules.token_issue` |
| `client` | Модуль с токеном `kind: client` — клиент хозяина | Всё, что может хозяин: все surface, включая `local`; доверие и модели; токены модулей |
| `service` | Модуль с токеном `kind: service` — мост, MCP, удалённый провайдер | Только объекты своих surface плюс свои `fs`/`sqlite`/`kv` |

Правила для `service`:

- **Surface.** Своя surface — та, у которой `surface.module` совпадает с id модуля (ключом его записи токена). Модуль не объявляет surface, а создаёт операцией `surfaces.create`; ядро записывает создателя, и больше ничто модуль с surface не связывает. Обслуживает surface живая сессия её создателя; встроенную `local` — каждая живая сессия `client`, `system` — никто.
- **Создание surface.** Только сессия модуля. `local` и `system` засевает ядро: `surfaces.create` с их id — `forbidden` любому. Чужой `id` — `conflict`: занять чужую surface нельзя. Если адрес хозяина в `chats.persons.master` привязан к модулю, surface этого адреса может создать только он, остальным — `forbidden`.
- **Чаты, история, blob'ы, `stats.chat_spend`** — только на своих surface. Blob без чата сервису недоступен.
- **Создание чата** — только на своей surface и только в папке с тем же эффективным trust, что у её `Unsorted`: модуль не может получить доверенный чат без действия хозяина.
- **Правка чата** — только `title`, `pinned`, `alerted`, `kind`, `project`, `workdir`, `workdir_on`. Поля `trusted`, `model`, `effort`, `thinking`, `compact_at` на surface, папке и чате меняет только хозяин.
- **Отказ без утечки.** За чужой и за несуществующий чат, папку, личность, blob сервис получает одинаковый `forbidden`; исключение — `surfaces.get`/`surfaces.update`: несуществующий id surface — `not_found` любому caller'у, чужой — `forbidden`; поиск чата по alias на чужой surface отклоняется до поиска; курсор `after` в списках проверяется той же видимостью. Списки `*.list` фильтруются в `WHERE` запроса.
- **Личности** — только `persons.resolve` адреса на своей surface.
- **События** — только по своим surface; события без surface (например, `module.*`) приходят только клиентам.
- **`inference.complete`** доступен и сервису; расход записывается на имя модуля.
- **Capability `ask`** — модуль рисует кнопки pending-запросов в чатах surface, которые обслуживает. В M1 она принимается и хранится; сами запросы появятся в M5.

### Что сервис-модуль не видит никогда

- чаты, историю и вложения surface `local`, `system` и surface других модулей;
- память, заметки, реестр личностей (кроме `resolve` своих адресов), папки;
- реестр моделей, глобальную статистику и расход, крон, сон, подагентов, реестр инструментов, гранты рук;
- список модулей и их токены;
- `fs`/`sqlite`/`kv` других модулей;
- полный транскрипт через capability `provider`: её принимают только у модуля, явно названного в `llm.providers` с `kind: module`, потому что провайдер видит всё, включая private-память. У остальных она отклоняется предупреждением в `welcome.warnings`.

### Текст, который попадает в промпт

Строки, которые модуль пишет в базу ядра, ограничены, иначе один сервис раздул бы базу, полнотекстовый индекс и системный промпт. Превышение — `invalid_params`.

| Поле | Потолок |
|---|---|
| Заголовок чата, имя surface, папки, личности, handle | 256 символов |
| `external_id` чата и личности | 256 байт |
| `project`, `workdir` чата | 4096 байт |
| `rules` surface | 16 KiB |
| `media_type` blob'а | 255 байт |

`rules` surface и описания инструментов, кроме того, отвергают строки, которые начинаются со служебных маркеров ядра, и управляющие или невидимые символы Unicode (формат Cf, U+2028/U+2029), которыми такой маркер можно замаскировать.

## Токены

- На токене ровно один бит прав — `kind`. Никаких списков грантов.
- **Идентичность — из токена.** Имени модуля в `hello` нет: ядро ищет предъявленный токен среди записей `modules.tokens` и строк `module_tokens`, id модуля — ключ найденной записи (его возвращает `welcome.module`). По нему вытесняются сессии и скоупятся surface и `fs`/`sqlite`/`kv`; назваться чужим именем модуль не может. Два ключа `modules.tokens` с одним токеном — отказ старта.
- **Id модуля** — `[a-z][a-z0-9_-]{0,63}`, оно же имя каталога его песочницы. `kernel`, `system`, `local` зарезервированы: такой ключ `modules.tokens` не даёт ядру стартовать, `modules.token_issue` отвечает `invalid_params`.
- **Хранение.** Выданные операцией `modules.token_issue` токены — 32 случайных байта в hex. Токен показывается один раз, в таблице `module_tokens` лежит только его blake3-хэш. Токены из конфига сравниваются тоже по blake3-хэшам, за постоянное время и без раннего выхода; токен конфига короче 32 символов — предупреждение на старте.
- **Приоритет конфига.** Если `modules.tokens` называет модуль, принимается только конфиговый токен, выданные для этого имени игнорируются, а `modules.token_issue` для него отвечает `conflict`.
- **Ротация.** У модуля один живой выданный токен: новая выдача отзывает прежний и закрывает его активные сессии с кодом `unauthorized` («module token rotated»). Выдать токен собственному модулю нельзя (`conflict`): ротация закрыла бы сессию, которая получает единственную копию нового токена.
- **Отзыв.** `modules.token_revoke {module}` отзывает выданные токены и закрывает сессии модуля с `unauthorized`. Нет живых выданных токенов (в том числе у модуля из `modules.tokens`) — `not_found`, сессии не закрываются; токен из конфига отзывается только правкой конфига и рестартом. Отзыв, случившийся во время handshake, сессии не даёт; запросы уже закрытой сессии не исполняются. Выдача и отзыв — только хозяину.
- **Отказ.** Неверный или пустой токен получает `unauthorized` после паузы 250 мс; вместе с лимитом handshake'ей на сеть это держит перебор на десятках попыток в секунду. Сбой базы при проверке токена уходит пиру как безликий `internal error`, подробности — только в лог. Handshake во время остановки ядра получает `unavailable`.
- **Один id — одна сессия.** Новая сессия с токеном того же модуля вытесняет прежнюю; сессии разных модулей живут одновременно.
- **Секреты в конфиге.** `modules.tokens.*.token`, `llm.providers.*.api_key`, `hands.endpoints.*.key` и `module.token` модуля на SDK — `SecretString` (`{file}` или `{plaintext}`): в логе вместо значения `<secret>`, читаются один раз на старте, от токенов модулей в памяти ядра остаются только blake3-хэши. Держите их файлом вне Nix store ([Быстрый старт](quickstart.md#секреты)). NixOS-модуль отдаёт такие файлы через `LoadCredential` и отказывает в сборке системы, если секрет попал бы в Nix store: `plaintext` в `settings`, переменная `EVA_*__PLAINTEXT` в `environment`, путь из Nix store в секрете, `extraConfigFiles` или `environmentFiles`.

## Песочница модуля

Каждая сессия модуля — и клиента, и сервиса — получает хранилища, адресуемые только своим id. Указать чужое имя в запросе нельзя: скоуп берётся из сессии. У самого ядра песочницы нет.

| Сервис | Где | Защита и лимиты |
|---|---|---|
| `fs.*` | `<state_dir>/modules/<module>/fs` | Путь только относительный; `..`, абсолютный путь и симлинк за пределы корня — `forbidden`. Объём — `modules.fs_quota` (по умолчанию 1 GiB), число файлов и каталогов — `modules.fs_max_entries` (100 000); превышение — `quota`, в том числе при параллельных записях. Чтение одного файла ограничено размером кадра |
| `sqlite.*` | `<state_dir>/modules/<module>/state.sqlite` | Соединение на вызов, WAL, `trusted_schema = off`. `ATTACH`, `DETACH`, `VACUUM` запрещены, лимит присоединённых баз — 0. Транзакции — только через `sqlite.tx`, не SQL-командами. PRAGMA — только из списка разрешённых; те, что сняли бы лимиты, доступны лишь на чтение. `sqlite.query` принимает только читающие операторы. Файл базы, временная база и временные файлы каждого вызова (сортировки, промежуточные b-tree, журналы операторов) — каждый до `modules.sqlite_quota` (1 GiB): их ведёт VFS ядра `eva-module`, временный файл вне бюджета вызова не растёт. Ответ `query` больше `modules.sqlite_max_rows` (10 000) строк или одного кадра — `quota`. Отмена вызова и `modules.request_timeout` прерывают оператор |
| `kv.*` | Таблица `module_kv` в базе ядра, ключ `(module, key)` | Ключ 1–1024 байта, значение — любое значение msgpack (включая `bin`) до `modules.kv_value_max` (1 MiB); всё KV модуля — до `modules.kv_quota` (64 MiB, ключ + значение + 64 байта на запись); last-write-wins |

Blob'ы (`blobs.*`) привязаны к чату и подчиняются правам чата. Размер одного blob'а — до `work.blob_max` (64 MiB). Живые blob'ы всех чатов одного владельца surface — до `work.blob_quota` (4 GiB; каждый blob весит не меньше 4 KiB; surface без модуля делят одну квоту), срок хранения — `work.blob_keep` (30 дней). Загрузка идёт во временный каталог `blob_dir/.staging` и не оставляет файлов при отмене; остатки подметаются на старте.

## Транспорт

| Слушатель | Защита |
|---|---|
| `{uds: path, mode, group}` | Права файла сокета (по умолчанию `0660`) и группа; относительный путь — от `system.state_dir` |
| `{ws: addr}` | Без шифрования; только для loopback или за обратным прокси с TLS |
| `{wss: addr, tls: {cert, key}}` | TLS на rustls с криптопровайдером ring; безопасные версии протокола по умолчанию (TLS 1.2 и 1.3); сертификат — PEM-цепочка, ключ — PEM; клиентские сертификаты не запрашиваются |

WebSocket-апгрейд принимается только на пути `/v1/modules`. Клиент `wss://` в `eva-sdk` доверяет публичным корням webpki; если задан `module.tls.extra_ca`, доверяет только этому CA (удобно для самоподписанного сертификата ядра).

Лимиты сессии защищают ядро от перегрузки одним модулем:

| Ключ `modules.*` | По умолчанию | Что ограничивает |
|---|---|---|
| `handshake_timeout` | 10 s | TLS, Upgrade и `hello` вместе |
| `max_hello` | 4 MiB (не больше `max_frame`) | Кадр `hello`; больше — `invalid_params` и закрытие |
| `ping_timeout` | 45 s | Тишина соединения; дольше — сессия закрывается |
| `request_timeout` | 60 s | Ответ на не-потоковый запрос и первый кадр потока |
| `max_frame` | 16 MiB | Размер кадра; больше — соединение закрывается |
| `max_inflight` | 64 | Одновременные запросы и загрузки сессии; сверх — `quota` |
| `max_streams` | 256 | Одновременные потоки сессии; сверх — `quota` |
| `blob_chunk` | 1 MiB | Чанк загрузки `blobs.put`; непрочитанные чанки всех загрузок сессии — до `stream_buffer × blob_chunk` |

Фиксированные лимиты, не настраиваемые конфигом:

| Что | Лимит |
|---|---|
| Соединения до `welcome` | не больше 64 на все слушатели и 8 из одной сети (IPv4 — адрес, IPv6 — /64); сверх новичок вытесняет старейшее соединение, ещё не приславшее `hello` |
| Сохранённые ответы окон идемпотентности | ответ больше 64 KiB не хранится (повтор получит `conflict`, а не второй эффект); окно — до 16 MiB и 16 384 записей; все окна вместе — до 64 MiB, сверх забываются старейшие ответы самого толстого окна |
| Новый `hello` модуля без `resume` | отвязывает прежние окна модуля: повтор запроса в них — `conflict`, а не второе исполнение |

Полный список ключей — в главе [Конфигурация](config.md).
